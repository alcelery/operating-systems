# Что мы прошли на паре: Потоки выполнения

## 1. Определение
- **Поток выполнения (execution thread)** — наименьшая единица обработки и выполнения инструкций в ОС. Является составной частью процесса: процесс может состоять из множества потоков или из одного.
- **Многопоточность** — свойство программы/среды, при котором она обладает несколькими потоками выполнения инструкций, работающими одновременно: на нескольких ядрах процессора или на одном ядре с иллюзией одновременности.

## 2. Параллелизм vs Конкурентность
| Понятие | Суть |
|---|---|
| **Параллелизм** | Исполнение инструкций в потоках независимо друг от друга, не пересекаясь (как параллельные прямые). Каждый поток работает в отдельном блоке АЛУ. Сложный раздел ИТ — не все инструкции можно вычислять независимо (NVIDIA CUDA, OpenMP). |
| **Конкурентность** | Исполнение инструкций «конкурентно» между потоками: потоки «отбирают» процессорное время друг у друга. На оба потока действует один блок АЛУ. Применяется для организации многозадачности в ОС. |

## 3. Сходства и различия потока и процесса
**Сходства:** оба обладают контекстом (идентификационный номер, набор регистров, стек); отвечают за многозадачность; представляют абстракции работы с данными.

| Процесс | Поток |
|---|---|
| Сущность, которой **выделяются** ресурсы ОС. | Сущность, которая **пользуется** ресурсами ОС. |
| Собственное адресное пространство. | Общая память со всеми потоками процесса. |
| Для взаимодействия нужны элементы межпроцессного взаимодействия. | Могут взаимодействовать друг с другом напрямую. |

## 4. Создание и переключение потоков
- **Создание:** достаточно выделить место под стек и создать контекст потока. Распределением ресурсов занимается подсистема управления процессами.
- **Переключение:** необходимо переключить контекст.
- **Когда переключаются потоки?** Когда действующий поток сам передал управление, либо когда ОС передаёт управление другому потоку.
- **Виды многозадачности:**
  - **Кооперативная:** поток передаёт управление только сам. *Плюсы:* не нужно реализовывать планирование, простота. *Минусы:* нужно проектировать взаимодействие потоков; задачи с большим I/O забирают процессорное время вхолостую.
  - **Вытесняющая:** поток «вытесняется» при израсходовании кванта ЦПУ, ожидании ввода/вывода, смене приоритета. *Плюсы:* нет простоя, нет «голода». *Минусы:* усложнённый контроль, необходимость планирования, сложно добиться «честности».

## 5. Планировщик и критерии планирования
- **Планировщик** — компонент ОС, определяющий, в какой момент с какого потока на какой переключить выполнение.
- **Критерии выбора потока:** количество исполняемых инструкций; время выполнения задачи; среднее время ожидания; наличие I/O операций; оценка по истории задачи (много I/O или много процессорного времени); предоставление равного кванта времени всем потокам.

## 6. Алгоритм Round-Robin
- В памяти очередь, потоки складываются по возрастанию идентификатора. Из очереди достаётся один поток, ему даётся квант процессорного времени. По истечении — поток в конец очереди, на его место приходит следующий. Поток может заранее отдать время при запросе I/O.
- **Квант времени:**
  - *Статический* — одинаков для всех. Больше квант → меньше времени на переключение, но дольше ожидание; меньше квант → больше времени на переключение, но короче ожидание.
  - *Динамический* — зависит от некоторого параметра.
- В современных ОС используются модификации Round-Robin с разными эвристиками, поэтому нет гарантии, в какой момент прервётся поток и в каком порядке они пойдут.

## 7. Модификации Round-Robin в ОС
- **Windows:** время потока зависит от приоритета; потоки с высоким приоритетом забирают всё процессорное время. При «голодании» приоритет повышается искусственно (Priority Boost).
- **Linux:** по умолчанию планировщик **CFS** — потоки поддерживают суммарное виртуальное время выполнения; упорядочиваются по убыванию этого времени, выбирается последний в списке. Исключение — потоки, долго бывшие в ожидании (например, I/O).

## 8. Синхронизация потоков
- **Состояние гонки данных (data race condition)** — проблема многопоточных приложений из-за неопределённости порядка выполнения инструкций нескольких потоков.
- **Решение:** работа с копиями данных или синхронизация потоков — обеспечение безопасного использования разделяемых ресурсов двумя и более потоками.
- **Определения:**
  - **Критическая секция** — участок кода, одновременно используемый не более чем одним потоком.
  - **Атомарная операция** — модификация данных, выполняемая целиком или не выполняемая вовсе.
  - **Семафор** — примитив синхронизации с атомарным инкрементом/декрементом (обычно 0 и 1).
  - **Блокировка (lock)** — механизм исключительного доступа к разделяемому ресурсу.
- **Механизмы синхронизации:** мьютекс (mutual exclusion, взаимное исключение потоков в критической секции); алгоритмы Деккера и Петерсона; RW-регистр (двоичный семафор о чтении/записи); условные переменные (взаимное исключение до выполнения условия).
- Поток, исключённый из выполнения, при получении процессорного времени либо ожидает в активном режиме (**spinlock**), либо моментально отдаёт управление (**yield**, кооперативность).

## 9. Deadlock (взаимная блокировка)
- Состояние, при котором два или более потока ожидают друг друга.
- **Подходы избежания:** Wait-For Graph, Wait-Die, Wound-Wait.

## 10. Классификация потоков
**По привилегиям:**
- Потоки уровня ядра (1:1)
- Потоки уровня приложения (N:1)
- Гибридные потоки (N:M)

**По многозадачности:**
- Потоки вытесняющей многозадачности — «нити»
- Потоки кооперативной многозадачности — корутины, файберы

**Реализации:**
| Уровень | Примеры |
|---|---|
| **Ядра** | POSIX Threads, Apple Multiprocessing Services, BSD Kernel Threads, WinAPI Threads |
| **Пользователя** | GNU Portable Threads, Apple Thread Manager, Netscape Portable Runtime, Ruby Green Threads |
| **Гибридные** | BSD Scheduler Activations, Solaris LWP | 

# Домашка: Администрирование

## Описание
Домашнее задание по дисциплине "Операционные системы и среды". Цель работы — отработать практику взаимодействия с процессами (`ps`, `grep`, `head`) и справочной системой `man`. Все задания выполняются на виртуальной машине (Debian) в терминале.

## Что понадобится
- Oracle VirtualBox с импортированным образом ВМ.
- Терминал ВМ.
- Word/PDF для оформления отчёта.

## Ход работы

| № | Задание | Команда / ответ |
|---|---------|-----------------|
| 1 | Отобразить процессы в виде дерева. Какие аргументы использовать? | `ps -e --forest` (или `ps -ef --forest`); `-e` — все процессы, `--forest` / `f` — вид дерева |
| 2 | Найти все процессы, запущенные не от root | `ps -u root -N` |
| 3 | Вывести пять процессов, потребляющих больше всего памяти | `ps -eo pid,user,rss,cmd --sort -rss \| head -n 6` |
| 4 | Вывести все процессы, запущенные в фоновом режиме | `ps -eo pid,user,tty,cmd \| grep "?"` (у фоновых процессов нет TTY) |
| 5 | В `man cp` найти аргумент для сохранения владельца, прав и меток времени | `man cp`; аргумент `-a` (`--archive`), то же что `-dR --preserve=all` |
| 6 | В `man man` найти аргумент поиска по ключевым словам | `man man`; аргумент `-k` (поиск по ключевым словам) |
| 7 | Найти команду, делающую то же, что в п.6, и найти страницы по слову "copy" | Команда `apropos` (эквивалент `man -k`): `man -k copy` или `apropos copy` |

## Замечания по выполнению
- В задании 1 `ps -e --forest` показывает все процессы в виде дерева; без `-e` видны только процессы текущего терминала.
- `-N` у `ps` инвертирует выбор: `ps -u root -N` = все процессы, кроме принадлежащих root.
- Для сортировки по памяти: `--sort -rss` (знак минус — по убыванию), `rss` — резидентная память.
- Команда `head -n 6` в задании 3 использована потому, что первая строка — заголовок таблицы, а пять нужных процессов идут после неё.
- Фоновые процессы определяются по отсутствию терминала: в столбце TTY стоит `?`.
- `apropos` — отдельная утилита, являющаяся синонимом `man -k`; результат поиска по `copy` включает `cp`, `scpio`, `install`, `scp` и др.

- В конце — вывод: какие знания извлечены, какие приёмы администрирования освоены.
