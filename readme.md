# Что мы прошли на паре: Межпроцессное взаимодействие (IPC)

## 1. Зачем нужно IPC
- Процесс изолирует свою память от вмешательства извне. Решая проблему разделённого доступа к ОЗУ, создали новую — **сложность коммуникации между процессами**.
- **Межпроцессное взаимодействие (IPC, inter-process communication)** — механизм обмена данными между двумя и более процессами.
- **Общий принцип всех способов:** раз память процессов изолирована, нужно создать дополнительную **буферную зону** с совместным доступом к данным.

## 2. Буферный файл
- Любой процесс имеет доступ к файловой системе через интерфейс системных вызовов → файл на ВЗУ можно использовать как буфер.
- **Недостатки и решения:**
  - Небезопасно (файл можно изменить извне/удалить) → политики безопасности (ACL, атрибуты ФС).
  - Сложно контролировать изменения → прерывание или другая внешняя функция контроля.
  - Скорость ограничена скоростью ВЗУ → использовать ОЗУ или другую быструю память.

## 3. Сигналы
- **Сигнал** — асинхронное уведомление процесса о каком-либо событии. Часть стандарта POSIX (в Windows — ограниченно).
- По умолчанию получение сигнала может вести к завершению процесса.
- **Сигналы Unix:** SIGHUP (потеря связи с терминалом), SIGINT (Ctrl+C), SIGSTOP (принудительная остановка без завершения), SIGTERM (запрос на завершение), SIGKILL (принудительное завершение), SIGPWR (авария питания), пользовательские SIGUSR1 и SIGUSR2.
- **Как послать:** в Windows — только POSIX-совместимые (SIGINT, SIGTERM, SIGALRM); в Unix — `kill` и `pkill` (например, `pkill -SIGUSR1 process`).
- **Что ещё можно:** пользовательским сигналам можно задать собственное поведение — перехватить сигнал и задать функцию через системный вызов `signal`. Своё поведение можно задать всем сигналам, кроме SIGKILL, SIGSTOP, SIGCONT, SIGRTMIN и SIGRTMIN+1 из POSIX Threads.

## 4. Каналы (pipes)
- **Канал (конвейер, pipeline)** — элементарный способ взаимодействия, похожий на буферный файл. При создании создаётся специализированный буфер с файловыми дескрипторами для чтения и записи.
- Используется для передачи данных между **родительским и дочерними процессами**; может быть создан только родительским процессом. В Windows понятия канала нет из-за отсутствия иерархии процессов.
- **Именованный канал (named pipe, FIFO)** — канал с уникальным символьным именем, по которому могут обращаться произвольные процессы. Реализован и в POSIX, и в WinAPI. Данные передаются потоком байтов.

## 5. Обмен сообщениями
- Сигналы не подходят для передачи осмысленных данных (только информация о состоянии) → концепция **сообщений**.
- **Сообщение** = числовой идентификатор + блок данных.
- В основе — **очередь**: добавление через `msgsnd`, изъятие через `msgget`. Получение сообщения **синхронное** (в отличие от асинхронного сигнала).
- Пример библиотек: **MPI (Message Passing Interface)** — для параллельных вычислений с разделением задачи на множество процессов со своими копиями данных.

## 6. Разделяемая память (shared memory)
- ОС позволяет процессу отобразить часть логического адресного пространства на произвольный блок физической памяти (при соответствующем уровне привилегий). Несколько процессов могут отобразить свои части на **общее физическое адресное пространство** — разделяемую память.
- **Объект (Unix):** `shmget()` — создание объекта и выделение участка; `shmat()` — присоединение к адресному пространству; `shmdt()` — отсоединение.
- **Сегмент (Unix):** `shm_open()` — выделение сегмента; `mmap()` — отображение в адресное пространство; `shm_unlink()` — удаление сегмента.

## 7. Сокеты
- **Сокет (socket)** — абстрактный объект, конечная точка подключения, определяемая в коммуникационном домене по определённому типу. Используется и для IPC, и для сетевого обмена.
- **Сокеты Беркли** (появились в BSD в 1982) — общая реализация в большинстве языков и ОС.
- **Коммуникационные домены:** LOCAL (IPC), INET (сеть), IPX (Novell IPX), PACKET (интерфейсы устройств).
- **Типы:**
  - `SOCK_STREAM` — потоковый, с контролем передачи данных.
  - `SOCK_DGRAM` — датаграмма, без контроля подключения.
- **Методы POSIX:** `socket()`, `bind()`, `connect()`, `listen()`, `accept()`, `read()/write()` или `send()/receive()`.
- В языках высокого уровня (например, C#) сокеты обычно реализуются на основе TCP/IP: классы `TcpClient`, `TcpListener`, `UdpClient`, `UdpReceiveResult`.

## 8. Дополнительные способы
- **Отображение файла в ОЗУ** через `mmap()` (memory map): запись/чтение как с файлом, но на скорости ОЗУ с контролем изменений; синхронизация с ВЗУ через `fsync`.
- **Process Trace (ptrace)** в Unix-подобных ОС — перехват данных и системных вызовов произвольного процесса и даже их подмена. Используется в **отладчиках (debugger)**: обработка системных ошибок, установка точек останова, чтение переменных и регистров, просмотр стека вызовов и т.п.

# Домашка: Администрирование 2

## Описание
Домашнее задание по дисциплине "Операционные системы и среды". Цель работы — научиться настраивать сетевой адаптер виртуальной машины, назначать IP-адрес и проверять связь между гостем и хостом с помощью команд `ip` и `ping`. Работа выполняется в VirtualBox на гостевой ОС Debian/Ubuntu Server.

## Что понадобится
- Oracle VirtualBox с импортированным образом ВМ.
- Хост-машина (Windows) с доступом к командной строке (`cmd`).
- Терминал гостевой ВМ.
- Word/PDF для оформления отчёта.

## Ход работы

| № | Задание | Команда / действие |
|---|---------|--------------------|
| 1 | Подключить второй адаптер: тип "Виртуальный адаптер", имя `VirtualBox Host-Only Ethernet Adapter`, включить кабель | Настройки ВМ -> Сеть -> Адаптер 2 |
| 2 | Получить информацию о сетевых интерфейсах | `ip address` |
| 3 | Назначить третьему адаптеру незанятый IP из сети `192.168.56.0` | `ip address add 192.168.56.3 dev enp0s8` |
| 4 | Проверить связь с самим собой (свой новый адрес) | `ping 192.168.56.3` |
| 5 | Проверить связь с хост-машиной | `ping 192.168.56.1` |
| 6 | Проверить связь из хост-машины в гостевую | В Windows: `ping 192.168.56.3` |

## Замечания по выполнению
- Первый интерфейс в выводе `ip address` — всегда `lo` (loopback, `127.0.0.1`), виртуальный, замыкается на себя.
- Второй интерфейс (`enp0s3`) — адаптер NAT по умолчанию, через него идёт выход в интернет.
- Третий интерфейс (`enp0s8`) — только что созданный Host-Only адаптер; до настройки он без IP.
- У адаптера может быть несколько имён: основное (`enp0s8`) и альтернативное (`enx...`). В отчёте использовалось альтернативное имя — это допустимо, но лучше ориентироваться на основное, которое выделено цветом в выводе `ip address`.
- IP `192.168.56.1` по умолчанию принадлежит хост-машине; в госте нужно брать свободный адрес из той же подсети, например `192.168.56.3`.
- В отчёте на шаге 6 из хост-машины ping не прошёл: "Заданный узел недоступен", 75% потерь. Возможные причины:
  - в госте не настроен ответ на ICMP или фаервол блокирует;
  - адаптер Host-Only в VirtualBox выключен или не поднят;
  - в госте интерфейс остался в состоянии DOWN (`state DOWN` виден в выводе `ip address` до назначения адреса);
  - адрес назначен на альтернативное имя, а маршрут/ARP идёт через другое.
- Чтобы связь из хоста заработала, стоит проверить `ip link set enp0s8 up`, настройки Host-Only адаптера в VirtualBox (Файл -> Менеджер сетей хоста) и отсутствие блокировки ICMP.
