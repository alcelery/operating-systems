# Что мы прошли на паре: Организация памяти

## 1. Физическая и логическая память
- **Физическая память** — память уровня контактов процессора; то, как процессор воспринимает информацию. **Физический адрес** — адрес контакта процессора или адрес памяти, мультиплексированный процессором.
- Важно: процессор может не выставить некоторые адреса; не всё, что выглядит как память, является памятью (по адресу можно обращаться к устройству/компоненту). Структура сложная: есть резерв, буферы, «дыры», VGA и т.д.
- **Проблема прямой работы с физической памятью:** каждое приложение должно знать структуру физической памяти — нерационально. Хотим, чтобы приложения видели память последовательно и не задумывались о структуре.
- **Логическая память** — абстракция для работы с памятью в виде логического адресного пространства. Каждый процесс изолирован и получает своё логическое адресное пространство; программа не привязана к одному месту в физической памяти.
- **Вывод:** ОС нужен механизм преобразования логического адресного пространства процесса в физическое — **преобразование адресов**.

| Логическая память | Физическая память |
|---|---|
| Абстрактная структура для процессов | Электронный контакт с адресом от процессора |
| Используется ОС | Используется процессором |
| Простая последовательная структура | Сложная структура: память, пустоты, не-память |

## 2. Сегментация
- **Идея:** разделить физическую память на сегменты одинакового размера; каждому процессу — свой сегмент. Решает проблему неравномерности памяти (устройства и пропуски игнорируются). Внутри сегмента адресация — смещением от начала.
- **Режимы:**
  - **Real Mode (16-bit):** `M_phys = SEG × 16 + OFF`. Сегментные регистры: CS, DS, ES, SS, FS, GS. Размер сегмента 64 Кб, максимум адресуемой памяти 1 Мб. Сегменты перекрываются (стоят на расстоянии 16 байт); минимальная единица между сегментами — **параграф** (4096 параграфов в сегменте). Частично решает проблему логической изоляции, но не доступа к памяти других процессов.
  - **Protected Mode (32-bit):** сегментные регистры хранят индекс в GDT/LDT и уровень привилегий. `M_phys = BASE(GDTR + SEG.INDEX) + OFF`. Дескриптор: BASE (32-бит адрес), LIMIT (20-бит размер, единица = 4 Кб), бит P (существование), системные флаги TYPE, G, DB, S, DPL, A.
  - **Long Mode (64-bit):** сегментация не используется, сегментные регистры хранят нули (кроме битов RPL).

## 3. Страничная организация памяти (пейджинг)
- **Идея:** как в словаре — отображение блоками фиксированного размера (**страницами**). Стандартный размер — 4 Кб или 64 Кб.
- **Требования к словарю:** не слишком большой, не тратить память на неиспользуемые страницы, быстрое отображение, простая структура (использует процессор).
- **Структура данных — цифровое дерево** (элемент узла — адрес следующего уровня).
- **Адрес разбивается на 5 частей:** PML4 (9 бит) → Directory Pointer (9 бит) → Directory (9 бит) → Table (9 бит) → Offset (12 бит). Первые четыре — по 512 записей по 8 байт; старшие 16 бит не используются (FFFF или 0000 в зависимости от 47-го бита).
- **Запись в таблицах:** физический адрес + флаги (чтение/запись, исполнение, существование, бит присутствия).
- **Бит присутствия (PS):** адрес ведёт сразу на страницу последнего уровня; offset занимает более 12 бит → страница может быть 2 Мб (2^21) или 1 Гб (2^30).
- **Скорость:** в сегментации — максимум 2 сложения и несколько чтений; в 4-уровневом пейджинге — 5 сложений и 6 чтений (медленнее).
- **Ускорение — TLB (Translation Lookaside Buffer):** кэш отображения логических адресов на физические. Возможен промах (TLB «непрозрачен»).
- **Отсутствие отображения:** при обращении процесса по такому адресу ОС производит исключение **Page Fault**. Бывает и обратное — несколько логических адресов на один физический.

**Paging vs Сегментация:**
| Paging | Сегментация |
|---|---|
| Память произвольной структуры | Память последовательная |
| Может содержать пустоты | Логическая память всегда отображена на физическую |
| Можно отобразить несколько логических адресов на один физический | Переход нескольких логических на один физический — нестандартное поведение |
| Позволяет организовать функциональную защиту доступа | — |

## 4. Память процесса
| Вид | Что хранится |
|---|---|
| **Автоматическая (стек, stack)** | Память фиксированной длины для каждого потока (обычно несколько Мб): локальные переменные, аргументы процесса, адреса функций, адреса фреймов. |
| **Статическая (SS)** | Блок фиксированного размера, общий на весь процесс, на всё время работы программы: данные только для чтения (константы), данные, определённые при компиляции, глобальные переменные, статические адреса. |
| **Локальная память потока (TLS)** | Статическая память, локальная по отношению к потоку: каждый поток хранит свою копию; хранится на протяжении выполнения инструкций потока (константы в потоке, глобальные переменные потока). |
| **Динамическая (куча, heap)** | Общий пул памяти, ограниченный размером ОЗУ; нужно запрашивать у ядра и контролировать время жизни объектов. За выделение/освобождение отвечают **аллокаторы**. Здесь хранится всё остальное, что не поместилось в другие области. |

Цель работы — освоить консольный мультиплексор tmux: создание и переименование окон, разделение рабочей области, переключение между областями и выполнение команд в разных панелях. ## Сокращения клавиш
- Префикс tmux — `Ctrl + B`. Далее идёт клавиша действия (нажимаются последовательно, не одновременно).

## Листинг скрипта (timer.py)

```
import time

start = time.time()
f = open("test.txt", "w")

while True:
    f.write(str(time.time() - start) + "\n")
    f.flush()
    time.sleep(1)
```

## Замечания по выполнению

- tmux-команды набираются последовательно: сначала префикс Ctrl + B, отпустить, затем клавиша действия (c, ,, 0, 1, %, ").
- В vim для выхода без сохранения: Esc, затем :q!; для сохранения: Esc, :wq.
- watch -n 1 'ls -l test.txt' показывает обновление размера файла раз в секунду. Через cat файл будет перерисовываться целиком, а не показывать рост — поэтому удобнее ls -l.
- f.flush() в скрипте нужен, чтобы данные сразу попадали в файл, а не копились в буфере.
- Деление окна: % — по горизонтали (панели слева/справа), " — по вертикали (панели сверху/снизу). Деления можно комбинировать.
- Переход между панелями: Ctrl + B, затем клавиши-стрелки.
- В отчёте на шаге 11 видна ошибка E: install: missing destination file operand after 'fastfetch' — это следствие опечатки в команде (apt install fastfetch набрано не полностью или с лишним пробелом). Правильная команда: apt install fastfetch.
- fastfetch — утилита вывода информации о системе (аналог neofetch).
