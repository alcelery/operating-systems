# Что мы прошли на паре: Структура ОС. Процесс загрузки ОС

## 1. Место ОС в системе
- **Схема взаимодействия:** Пользователь (оператор) → Операционная система → Аппаратное обеспечение.
- ОС — это «прослойка» между человеком и «железом», предоставляющая интерфейс и управляющая ресурсами.

## 2. Функции ОС (напоминание)
- Абстракция работы с устройствами;
- управление вводом/выводом;
- взаимодействие с постоянной памятью;
- управление оперативной памятью;
- мультипрограммирование и многозадачность;
- управление процессами и их взаимодействием;
- разграничение полномочий;
- управление графической подсистемой.

## 3. Прикладное ПО
- **Прикладное ПО** — программы для решения конкретных задач пользователя.
- Может быть встроенным (в составе окружения рабочего стола) или отдельным.
- Одно и то же прикладное ПО может разрабатываться под разные ОС.

## 4. Подсистемы ОС
| Подсистема | Задачи |
|---|---|
| **Управления сеансами** | Регистрация сеанса, хранение информации о сеансе, завершение сеанса. *Сеанс* — время работы пользователя с ОС для решения задач. |
| **Управления процессами** | Распределение ресурсов между задачами, защита памяти процессов, межпроцессное взаимодействие. *Процесс* — совокупность информационного окружения и области памяти с исполняемым кодом и данными. |
| **Графическая** | Управление ресурсами графического ускорителя, выводом на дисплей, корректное отображение сеансов рабочего стола. |
| **Файловая** | Преобразование данных с запоминающих устройств в логические объекты (файлы/каталоги) и обратно; разграничение доступа. |
| **Ввода/вывода** | Обработка запросов подсистем, преобразование в вызовы логических устройств, обращение к драйверам физических устройств. |

## 5. Связь с аппаратной частью
- **Драйвер устройства** — ПО, через которое подсистемы ОС взаимодействуют с «железом». Чаще всего реализуются подключаемыми модулями (динамическая загрузка).
- **Прерывание (interrupt)** — специальная процедура, связанная с внешними событиями. При прерывании система «прерывает» основную работу и запускает обработчик прерывания.

## 6. Связь с прикладным ПО
- Доступ к подсистемам ОС — через **интерфейс системных вызовов** (набор библиотек: ABI или API), где реализованы функции обращения к подсистемам.

## 7. Полная структура ОС (снизу вверх)
1. **Аппаратное обеспечение**
2. **Драйверы устройств**
3. **Подсистема ввода/вывода**
4. **Интерфейс системных вызовов**
5. **Прикладное ПО** (в т.ч. встроенное)
6. **Пользователь (оператор)**

*Сбоку — подсистемы: управления сеансами, процессами, работы с файлами, графическая.*

## 8. Состав ОС по назначению
- **Системные утилиты пространства пользователя** (работают в ограниченном режиме).
- **Подсистемы аппаратно-программного уровня (ядро)** — работают в привилегированном режиме.

## 9. Ядро ОС
- **Ядро (kernel)** — центральная часть ОС, обеспечивающая координированный доступ прикладного ПО к ресурсам компьютера; выполняет все функции управления ресурсами.
- **Второе определение:** ПО, работающее с аппаратной частью, обрабатывающее прерывания и системные вызовы, и **единственное ПО, выполняющее инструкции в привилегированном режиме**. Всё остальное — в ограниченном.

## 10. Привилегированный и ограниченный режимы
- **Иерархические домены защиты (кольца защиты, protection rings)** — механизм контроля доступа к инструкциям процессора.
- На практике два уровня: **ring0** (полный набор инструкций, ядро) и **ring3** (ограниченный набор, приложения).
- Для доступа приложений к «железу» используется интерфейс системных вызовов.

## 11. Виды ядер
| Вид | Суть | Представители |
|---|---|---|
| **Монолитное** | Реализует все подсистемы и драйверы в одном пространстве. Классика, самая распространённая модель. | Unix, MS DOS, первые версии Linux |
| **Модульное** | Усовершенствованное монолитное: позволяет динамически загружать модули ядра (объектные файлы для оборудования). | Linux, BSD |
| **Микроядро** | Минимальный набор функций (управление процессами, вводом/выводом, памятью). Остальное (драйверы, ФС) — в пространстве пользователя как отдельные процессы. | Minix, Mach, GNU Hurd, ранние Windows NT |
| **Гибридное** | Модифицированное микроядро: совмещает принципы монолитного и микроядра; часть сервисов — прямо в ядре. | Поздние Windows NT, ReactOS, Darwin XNU (macOS) |
| **Другие** | Наноядро (только обработка прерываний: KeyKOS, Adeos Linux), экозядро (IPC + память: Nemesis, BareMetal), мультиядро (для многоядерных систем: Barrelfish). | — |

**О микроядерной архитектуре:** ядро реализует малую часть подсистем в привилегированном режиме; основная подсистема — **IPC** (межпроцессное взаимодействие). Остальные компоненты — «серверы ОС», работают в ограниченном режиме.

## 12. Загрузка ОС — 5 этапов
1. **BIOS (UEFI)** — первая инструкция: для x86 чтение по адресу `0xFFFFFFFF`, отвечает материнская плата → передаёт управление firmware (BIOS/UEFI).
   - BIOS выполняет **POST** (проверка регистров процессора, ОЗУ, контроллеров, CMOS, таймера), начальную инициализацию оборудования, поиск загрузочных устройств.
2. **Bootstrap** — загрузочный сектор (первые 512 байт ПЗУ: читаемы, последние 2 байта `0x55` и `0xAA`, код помещается по адресу `0x7C00`). Код весом ≤510 байт передаёт управление вторичному загрузчику.
3. **GRUB (вторичный загрузчик)** — имеет небольшую копию ОС, умеет работать с FAT32; знает только раздел **EFI**, где лежат сжатый образ ядра, `initrd` и конфигурация запуска. Подгружает данные в ОЗУ и передаёт управление ядру.
4. **Kernel + initrd** — ядро получает драйверы и компоненты; из `initrd` запускается первый процесс, дающий команду на инициализацию системы.
5. **Userspace** — переход в пространство пользователя, запуск полноценной ОС.

**Цепочка загрузки:** `BIOS → Bootstrap → GRUB → Kernel + initrd → Userspace`

# Домашка: Использование простых команд

## Описание
Домашнее задание по дисциплине "Операционные системы и среды". Цель работы — отработать на практике базовые команды Linux: `cd`, `ls`, `cat`, `grep`, `find`. Все задания выполняются на виртуальной машине (Debian) в терминале от пользователя root.

## Что понадобится
- Oracle VirtualBox с импортированным образом ВМ (см. ДЗ по снимкам).
- Терминал ВМ, вход как root.
- Word/PDF для оформления отчёта.

## Ход работы

| № | Задание | Команда |
|---|---------|---------|
| 1 | Перейти в `/var/log` и показать все файлы с расширением `.log` | `find /var/log -name "*.log"` |
| 2 | Перейти в `/usr/bin` и показать файлы, отсортированные по размеру | `ls -lS` |
| 3 | Отобразить содержимое `/etc/apt/sources.list` | `cat /etc/apt/sources.list` |
| 4 | В `/etc/passwd` найти все строки, содержащие `root` | `grep root /etc/passwd` |
| 5 | В `/etc/services` вывести строки без комментариев (без `#`) | `grep -v "#" /etc/services` |
| 6 | Найти в `/etc` все файлы и директории с `.conf` или `.conf.d` одной командой | `find /etc -name "*.conf" -o -name "*.conf.d"` |
| 7 | Определить число объектов типа "ссылка" в корневом каталоге | `find / -type l` (подсчёт: `find / -type l \| wc -l`) |
| 8 | В `/usr/share` найти каталоги на глубине не более 2 уровней | `find /usr/share -maxdepth 2 -type d` |
| 9 | В `/var` найти все файлы, принадлежащие пользователю root | `find /var -type f -user root` |
| 10 | В `/etc` в пределах 2 каталогов найти файлы, внутри которых упоминается `root` | `find /etc -maxdepth 2 -type f -exec grep -l root {} \;` |

## Замечания по выполнению
- `-S` (заглавная) в `ls` сортирует по размеру, `-s` (строчная) — выводит размер в блоках. Это разные вещи.
- В задании 7 подсказка в презентации содержит опечатку: тип ссылки — строчная буква `l` (L), а не цифра `1`.
- Для подсчёта количества ссылок удобно добавить `| wc -l` к команде `find`.
- В задании 10 `-exec grep -l root {} \;` выводит только имена файлов (`-l`), где встречается слово.
- Полезно использовать `--help` у команд для изучения дополнительных параметров.

## Требования к отчёту
- Оформляется в Word/PDF.
- Каждый шаг фиксируется: команда + скриншот вывода.
- В конце — вывод: какие знания извлечены, какие параметры команд изучены.
