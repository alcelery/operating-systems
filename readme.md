# Что мы прошли на паре: Модель процесса

## 1. Программа и процесс
- **Программа** — хранимый набор инструкций и данных, представляемый в ОС как исполняемый файл. Для перемещения из ПЗУ в ОЗУ нужен программный загрузчик.
- **Процесс** — совокупность окружения и области памяти, содержащей код и данные исполняемой программы.
- **Связь:** `Программа + Окружение программы (системная информация) = Процесс в ОС`.

## 2. Контекст процесса
**Контекст процесса** — совокупность системных данных, характеризующих процесс и существующих всё время его выполнения. Состоит из трёх частей:

| Часть | Содержимое |
|---|---|
| **Пользовательский контекст** | Код, данные, стек. |
| **Регистровый контекст** | Регистры процессора (СОЗУ на кристалле): счётчик команд (IP), состояние процессора (FLAGS), указатель стека (SP), регистры общего назначения (AX, BX, CX, DX, SI, DI, R8–15) и специального назначения (CS, DS, SS, ES, FS, GS, BP, CRO). |
| **Контекст системного уровня** | Данные ядра для межпроцессного взаимодействия. *Статическая часть:* дескриптор процесса, список адресов и размер памяти, PID, Parent PID (Unix), приоритет, идентификатор пользователя, макс. размер адресного пространства. *Динамическая часть:* секты в пространстве ядра, пользовательская область, время выполнения, результаты системных вызовов, открытые файловые дескрипторы. |

**Зачем так много данных?** ОС поддерживает мультипрограммирование (многозадачность даже на одном вычислительном блоке). Подсистема управления процессами переключает контексты, чтобы конкурентно исполнять множество задач. При переключении контекст сохраняется/восстанавливается полностью (стек, регистры) — управление процессом восстанавливается в полном объёме.

## 3. Создание процесса
- **Когда?** При загрузке ОС (первый процесс запускается при загрузке ядра) или при появлении соответствующего сигнала.
- **Как?** По одному сценарию через системный вызов: выделить уникальный **PID**, выделить память под инструкции и стек, создать запись о процессе.
- **Схема:** Пользователь → Приложение / Подсистема ввода/вывода (перехват сигнала на запуск) → Подсистема управления процессами (создание контекста, выделение PID) ↔ Подсистема управления памятью (перенос инструкций в ОЗУ, сохранение регистров и стека).

## 4. Завершение процесса
- **Когда?** Причины разные — поведение подсистемы управления процессами зависит от причины.
- **Причины:**
  1. **Штатное завершение** — возврат из точки входа (`main` в C/C++); обычно `return 0` при отсутствии проблем, другое значение — возможная ошибка.
  2. **Внешний сигнал** — утилита `taskkill` или другая программа внешнего завершения; также Ctrl+C / Break.
  3. **Ошибка времени выполнения** — логические ошибки инструкций (деление на 0, изменение защищённой памяти, необработанное исключение).
- **Механика:** процесс покидает планировщик → подсистема управления памятью собирает статистику → удаляет инструкции и ресурсы из ОЗУ → удаляет контекст процесса. Любое завершение ведёт к **разворачиванию стека (stack unwinding)** для безопасного удаления данных.
- **Сигналы Unix:** SIGHUP (потеря связи с терминалом), SIGINT (Break), SIGSTOP (принудительная остановка без завершения), SIGTERM (запрос на завершение), SIGKILL (принудительное убийство), SIGPWR (авария питания) и др. Остановка может быть мягкой или жёсткой, сигнал обрабатывается процессом или ОС.

## 5. Иерархия процессов
- Процесс создаётся либо при загрузке ОС, либо только другим процессом → иерархия описывается **деревом** (родитель → потомки).
- **Windows:** иерархии как таковой нет, на уровне ядра все процессы равнозначны; есть лишь метка о вызвавшем приложении.
- **Unix:** вся система построена на иерархии. Единственный процесс без родителя — **init (PID = 1)**, создаваемый при загрузке ядра. У остальных в дескрипторе есть поле **PPID** (Parent PID).

## 6. Состояния процесса (жизненный цикл)
Создан → Готов к запуску → Выполняется в режиме задачи / Выполняется в режиме ядра → (Ожидание / Блокировка) → Зомби → Завершён.

- **Ожидание** — например, процесс ждёт ввода данных от пользователя.
- **Блокировка** — например, процесс обращается к устройству, которое сейчас недоступно.
- **Зомби (Unix)** — процесс успешно завершён, но родитель не получил об этом информацию, поэтому ОС держит контекст в памяти. Обозначается `<defunct>`.

## 7. Приоритет процесса
- Используется для **контроля времени выполнения** конкретного процесса: чем выше приоритет, тем больше процессорного времени.
- Может меняться: например, у приложения в ожидании данных приоритет низкий, а у главного приложения в ОСРВ — высокий (для максимального отклика).

# Домашка: Использование простых команд 2

## Описание
Домашнее задание по дисциплине "Операционные системы и среды". Цель работы — отработать практику взаимодействия с файловой системой (создание каталогов и файлов, переименование, чтение) и работу с потоками ввода/вывода (перенаправление `>`, `>>`, конвейер `|`). Все задания выполняются на виртуальной машине (Debian) в терминале.

## Что понадобится
- Oracle VirtualBox с импортированным образом ВМ.
- Терминал ВМ.
- Текст первых двух абзацев книги "Гарри Поттер и философский камень" (на английском, каждое предложение с новой строки).
- Word/PDF для оформления отчёта.

## Ход работы

| № | Задание | Команда |
|---|---------|---------|
| 1 | Создать каталог `work` в домашней директории | `mkdir work` |
| 2 | Перейти в каталог и вывести текущий путь | `cd ./work` + `pwd` |
| 3 | Создать пустой файл `file.txt` | `touch ./file.txt` |
| 4 | Заполнить файл текстом (первые два абзаца, каждое предложение с новой строки) | `echo "..." > file.txt` (первая строка), затем `echo "..." >> file.txt` (последующие) |
| 5 | Переименовать файл в `book.txt` | `mv ./file.txt ./book.txt` |
| 6 | Прочитать файл и проверить корректность вставки | `cat book.txt` |
| 7 | Найти предложения со словом `was` и записать в `was.txt` | `grep was book.txt > was.txt` |
| 8 | Объединить `was.txt` и `book.txt`, посчитать количество букв `n` | `cat book.txt was.txt > combo.txt` + `grep -o n combo.txt \| wc -l` |

## Замечания по выполнению
- Первая запись в файл выполняется через `>` (перезапись), последующие — через `>>` (дозапись).
- `echo` с текстом в кавычках: если внутри текста есть одинарные кавычки (например, `you'd`), внешние кавычки лучше делать двойными.
- `mv` используется для переименования: "перемещение" файла в ту же директорию под другим именем = переименование.
- Для подсчёта вхождений буквы `n` флаг `-o` у `grep` выводит каждое совпадение на отдельной строке, а `wc -l` считает строки, то есть количество вхождений.
- Внимание: `wc -l` — строчная буква `L`, а не цифра `1`. В отчёте была опечатка `wc -1`, из-за чего команда выдала ошибку `invalid option`.
- При объединении `cat book.txt was.txt > combo.txt` строки со словом `was` будут повторяться (они есть и в `book.txt`, и в `was.txt`) — это нормально и влияет на итоговое число.

## Требования к отчёту
- Оформляется в Word/PDF.
- Каждый шаг фиксируется: команда + скриншот вывода.
- В конце — вывод: какие знания извлечены, какие приёмы работы с файлами и потоками освоены.
